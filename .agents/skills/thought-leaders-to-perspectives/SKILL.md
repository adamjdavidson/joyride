# Thought leaders to perspectives

Produce an editable thinking lens grounded in a person's documented work. Its value is the different questions and decisions it brings to the user's problem. Treat the result as an experimental interpretation, not an impersonation, endorsement or complete account of the person.

## Select for a useful difference

Start with the user's subject, desired tension and existing perspectives. Honor their selected figures and exclusions. When candidates are needed, propose a small contrasting set of public figures: explain the intellectual move each offers and where it overlaps the existing roster. Popularity alone is weak evidence of a useful lens. Use an unnamed method when attribution would add little or the proposed person is private.

## Establish the method

Read primary sources: the person's published work, talks, interviews or documented practice. Use trusted scholarly interpretation where primary material needs historical or conceptual context; identify it as secondary. Record exact source links and the passages or sections that support each claimed method. Separate source-backed observations, contested interpretations and your operational adaptation. If sources cannot be accessed, mark the profile provisional and identify the evidence needed; never turn memory into a fabricated citation.

Look for what the thinker notices, which questions they ask, how they test an explanation, what they resist, and what changes their mind. Prefer a few distinctive operations over a list of admirable traits. A perspective about power should make choices about incentives or stability; “be insightful and strategic” supplies little behavior.

## Turn evidence into an editable lens

Write a concise profile with:

- Its useful tension and strongest questions.
- Concrete response behaviors and failure modes, each connected to evidence or labeled as adaptation.
- Limits: where the lens is speculative, dated, inappropriate or easily caricatured.
- A short instruction block and illustrative response on the user's topic.

Use plain language. Describe a lens inspired by public work; avoid invented quotations, private beliefs, personal memories and claims that the person endorses it. Hypotheses about motives stay hypotheses. The lens may challenge, expand or implement when useful; it should not be trapped in a single activity just because of its label.

## Compare behavior and integrate when requested

Use the same concrete input for two contrasting lenses. Check whether they notice different things and take different next steps. Also try a case outside the lens's domain and verify it can admit its limits. Revise generic wording or caricature revealed by these comparisons. Label authored sample outputs as illustrative; report actual model tests separately.

For Joyride integration, read docs/CUSTOMIZING.md and public/joyride-config.js in the target repository. Add the entry to `perspectives` with a stable ID, display fields, `instructions` and an explicitly prepared `sample`. Keep the source rationale in a short linked research note. The shared registry supplies the web selector, live prompts and metadata validation. Optional firmware rosters and portraits are separate integrations; change them only if requested. Run the repository checks and confirm that visiting and leaving the new lens works.

Completion means the user has an editable profile, traceable evidence, a clearly labeled adaptation, and a meaningful contrast with another lens. Selecting a person or drafting a profile alone does not authorize publishing it or generating their portrait.
